# AxiomWeave Risk Atlas and Unified Research

The existing Apex taxonomy mixes real operational risks with unimplemented hardware and physics hypotheses. Its synthetic scorecard does not establish live trading performance. This change preserves a searchable finite catalog, adds explicit measurement/correspondence gates, and connects actual CABS composition and optional AS3-R replay through a bounded read-only MCP.

## Contracts and scope

`axiomweave-risk-atlas` exposes a 240-scenario, 60-family declared catalog, question framing, supplied-measurement controls, supplied-position portfolio stress accounting, and bounded frontier suggestions. The first 216 scenarios preserve the source taxonomy; the next twelve preserve the original Section 7 labels; twelve additional scenarios test feasibility and correspondence. Original hyperbolic/quantum/hardware names are provenance labels, not claims about implemented systems.

`axiomweave-unified-research` adds CABS catalog/search/cost tools, a combined typed question/control/portfolio probe, and a pinned optional AS3-R executable adapter. Search uses actual CABS type and cost routines. AS3-R replay uses actual JSON-RPC calls to the configured, hash-pinned executable. Missing adapters fail closed. User tool input cannot supply executable paths, shell commands, credentials, or arbitrary imports.

Twenty-four operational checks use supplied numeric or boolean measurements. Missing inputs produce `unknown`, never a safe default. Non-finite numbers, incorrect units/types, unknown measurement fields, future/stale timestamps, and invalid enum values are rejected or produce a failed check. Thresholds are explicit experimental policy assumptions, not estimates of win probability.

Portfolio stress tests compute linear spot/notional P&L under supplied finite shocks; cash, no-change, and equal-budget random controls remain distinct. Options, nonlinear liquidation, broker execution, and causal financial claims need separate backends. Unknown costs propagate. Exhaustive enumeration covers only a frozen finite grammar. Beam search remains incomplete; Apriori is accepted only after the canonical subset predicate audit.

## Verification and rollout

Freeze catalog, code hashes, tests, seeds, input universe, and cost/risk budgets. Exercise boundary values, NaN/infinity, wrong field types, missing observations, irrelevant risk flags, pairwise operational faults, stock-shock arithmetic, CABS exhaustive/beam/Apriori controls, AS3-R actual IPC, protocol notifications, and SDK client cleanup. Preserve failures. Limits: at most three declarative research rounds, 256 supplied stress scenarios, 64 positions, 4096 CABS candidates and the canonical search's 10-second bound. No generated code or unattended financial actions.

Before registering configurations or changing live source, retain hash-verified source/config backups. Register only named servers, preserve unrelated config values, verify direct and available live-client calls, disconnect temporary clients, and restore local MCPs off. Config registration is distinct from fresh IDE runtime discovery. A source change invalidates adapter pin verification.

Live deployment is a separate narrow repair: exercise actual scan branches under stubbed market/time inputs, fix demonstrable variable errors, record rejection reasons without altering financial state, and restart only the classified alert service after tests. New speculative strategies and exotic scientific mechanisms are not promoted to live execution. Source rollback never restores financial ledgers.

## Evidence packet

The local owner packet records source hashes, provenance, current service/log observations, before/after archives, negative controls, receipts, C0-C2 claim ceilings, falsifiers, and stop rules. Public artifacts contain no private chats, credentials, personal host paths, or account identifiers. The route is one implementation owner with a centralized skeptical reviewer. C1 mechanics and C2 historical observations do not earn prospective, causal, universal, or profit claims.
